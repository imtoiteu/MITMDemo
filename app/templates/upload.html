🦈 How Wireshark Sees It

{% if demo_mode == "HTTP" %}
HTTP POST multipart — Plaintext
POST /upload/ HTTP/1.1
Host: 127.0.0.1:{{ http_port }}
Content-Type: multipart/form-data; boundary=----Boundary123

------Boundary123
Content-Disposition: form-data; name="file"; filename="secret.txt"
Content-Type: text/plain

This is the SECRET file content.
Wireshark can read every byte.
------Boundary123--

The raw file bytes appear inside the multipart body. For text files, they are immediately readable. Binary files (images, PDFs) can be exported using Wireshark's File → Export Objects → HTTP.

{% else %}
TLS Application Data — Encrypted
17 03 03 04 7f 3a c8 d1 9e f2 ...
[opaque TLS ciphertext]
← Filename, file contents,
  MIME type all hidden

Over HTTPS the entire multipart body — including filename and file content — is encrypted. The packet capture reveals nothing about the uploaded file.

{% endif %}

📌 Key Takeaways

  • Over HTTP, every byte of an uploaded file is visible to a network observer.
  • This includes text files, images, PDFs, and sensitive documents.
  • Wireshark's Export Objects feature can reconstruct and save the file from the capture.
  • HTTPS (TLS 1.3) encrypts both the file content and its metadata (filename, type, size).
  • Always use HTTPS for any file or form upload — especially on public networks.
